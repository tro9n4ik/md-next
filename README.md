# MD-Next

MD-Next — веб-панель для управления VPN-сервером и кластером узлов. Серверная часть построена на FastAPI, SQLAlchemy и SQLite; клиентская — на React, TypeScript и Vite.

## Возможности

- Управление клиентами и профилями VLESS Reality, VLESS XHTTP, Hysteria 2 и AmneziaWG.
- Подписки для совместимых клиентов; профиль DNS для Happ передаётся заголовком `routing`.
- Срок подписки: неделя, месяц, год, произвольная дата или бессрочно. Месячный
  лимит трафика необязателен и обновляется от даты создания клиента.
- Управление узлами кластера, ручное переключение выхода и автоматическое переключение на резервный узел и возврат к основному.
- Правила маршрутизации Xray, включая direct, block, proxy и WARP.
- Управление WARP, настройками протоколов, DNS, Telegram и безопасностью.
- Журнал событий, статистика трафика, состояние сервера и двухфакторная аутентификация.

## Установка на сервер

Установщик рассчитан на Ubuntu/Debian и требует root-доступа. Перед установкой настройте DNS-записи доменов на адрес сервера. Нужны основной домен и поддомен панели; для выдачи сертификатов они должны быть доступны снаружи.

Скопируйте проект на сервер и запустите скрипт из его каталога:

```bash
git clone https://github.com/tro9n4ik/md-next.git
cd md-next
sudo bash scripts/install.sh
```

При запуске появится меню: установить, обновить или удалить MD-Next. При первой установке скрипт запросит основной домен, домен панели и электронную почту администратора. После установки он покажет пароль администратора; сохраните его в надёжном месте.

Скрипт настройки узла `scripts/join-node.sh` запускается на дочернем сервере по одноразовой команде-приглашению из панели. Не публикуйте URL приглашения и его токен.

### WARP через зарубежную ноду

Новые приглашения автоматически настраивают бесплатный WARP на ноде в режиме
локального SOCKS5. Лицензия не требуется. Поддерживаются Ubuntu 22.04/24.04/26.04
и Debian 12/13. Если WARP не настроился, сама нода продолжает работать;
подробности находятся в `/tmp/md-next-node-install.log`. Для подключения ноды
без установки WARP передайте команду скрипту через `MD_NEXT_NODE_WARP=0 bash`.
Существующий WARP автоматически не перенастраивается и не перерегистрируется.

Во вкладке WARP выберите сервер выхода, оставьте порт 40000 и при необходимости
укажите проверяемый код страны, например `DE`. «Проверить и сохранить» сначала
проверяет отдельное соединение, затем применяет маршрут. Готовые правила ИИ
используют выбранный WARP; обычный выход через ноду сохраняется.
Страну определяет Cloudflare: код страны задаёт условие проверки, а не регион
туннеля. Доступность конкретного сервиса и аккаунта проверяется отдельно.
При недоступности выбранного WARP автоматического выхода через сервер панели нет.

На существующей ноде установите официальный `cloudflare-warp`, задайте
`warp-cli --accept-tos mode proxy` до регистрации и подключите прокси на
127.0.0.1:40000. В актуальном Xray для Freedom потребуется узкое `finalRules`:
`{"action":"allow","network":"tcp","ip":["127.0.0.1/32"],"port":"40000"}`.
Не открывайте SOCKS5-порт в интернет. Из панели проверяется сам выход;
управление службой WARP ноды выполняется на ноде. Автоматический установщик
создаёт `/var/backups/md-next/warp-node-<дата>/rollback.sh` для отката WARP.

### Резервное копирование

На сервере `scripts/backup.sh` создаёт архив с базой данных, `.env` и конфигурациями Xray, AmneziaWG и Nginx. Копия базы снимается через SQLite Backup API, поэтому остаётся целостной даже при работающей серверной части, и проверяется командой `PRAGMA integrity_check`.

```bash
sudo bash scripts/backup.sh          # создать копию
sudo bash scripts/backup.sh --list   # показать существующие копии
```

Копии по умолчанию складываются в `/var/backups/md-next`, хранятся последние 7 штук, архивы имеют права `600`. Пути и глубину ротации можно переопределить: `BACKUP_ROOT=/путь KEEP=14 sudo -E bash scripts/backup.sh`.

## Разработка

### Бесплатный WARP

На вкладке WARP нажмите «Включить WARP», затем примените нужные готовые правила.
Ключ нужен только для платного WARP+ и находится в дополнительных настройках.
Если есть доступная нода, бесплатная регистрация выполняется через неё. Для
этого временная служба создаёт отдельный локальный прокси Xray с выходом только
через выбранную ноду. Правила HTTPS затрагивают только группу `warp-svc` и адреса
API регистрации; TLS не расшифровывается. Общие маршруты сервера не меняются.
После регистрации прокси и правила удаляются, а WARP подключается напрямую.
Служба ограничена по времени; `ExecStopPost` очищает правила даже при остановке
панели. Нужны systemd, iptables с поддержкой cgroup v2 и root-доступ службы панели.
Без доступной ноды выполняется обычная прямая регистрация Cloudflare.

Панель проверяет реальный выход через SOCKS5 до сохранения настроек. При сбое
восстанавливает прежние режим и порт. Существующая регистрация сохраняется.
Выбор пресетов и режима использования выполняется администратором. Страна
выхода определяется Cloudflare; WARP не гарантирует нужную страну для сервисов.

### Сроки и месячный трафик

В форме нового клиента выберите срок подписки и, при необходимости, лимит в ГБ
(1 ГБ = 1024³ байт). По умолчанию в форме — месяц и трафик без ограничений.
Существующие клиенты после миграции остаются бессрочными; их суммарные счётчики
и ранее заданные суммарные лимиты сохраняются. API без новых параметров также
создаёт бессрочного клиента для обратной совместимости.

На странице доступа можно продлить срок или задать точную дату. Продление
прибавляется к текущему сроку, а для истёкшей подписки — к текущему времени;
оно не сбрасывает трафик. Месячный период привязан к дате и времени создания
в UTC. Например, 31 января → последний день февраля → 31 марта.
Неиспользованный трафик не переносится. Новый месяц автоматически возвращает
доступ при исчерпанной квоте, сохраняя ручное отключение и истёкший срок.

Ограничения применяются ко всем профилям, включая AmneziaWG. Сборщик проверяет
сроки и квоты раз в минуту; возможна задержка до одного цикла. Счётчики берутся
из Xray и AmneziaWG, поэтому лимит является ограничением по измеренному трафику.
Подписка передаёт срок и лимит в `Subscription-Userinfo`, а для недоступного
клиента возвращает пустой список. Суммарный трафик хранится отдельно от месячного.

Перед обновлением работающей установки сделайте резервную копию, остановите
серверную часть, обновите исходники и выполните `alembic upgrade head` из backend
в её виртуальном окружении. Новая миграция `0010_client_limits` добавляет столбцы,
не меняя существующие профили. При откате исходников сохраняйте рабочую базу:
старая версия не применяет новые условия подписок. Не выполняйте downgrade
миграции на базе с уже настроенными сроками и лимитами.

Требуются Python 3.11 или новее и Node.js с npm. Команды выполняются из корня проекта.

### Серверная часть

```bash
cd backend
python -m venv .venv
```

Linux/macOS:

```bash
source .venv/bin/activate
pip install -r requirements.txt
export JWT_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_urlsafe(48))')"
export INITIAL_ADMIN_PASSWORD="Задайте-длинный-уникальный-пароль"
alembic upgrade head
uvicorn app.main:app --reload
```

Windows PowerShell после активации окружения:

```powershell
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
$env:JWT_SECRET_KEY = python -c "import secrets; print(secrets.token_urlsafe(48))"
$env:INITIAL_ADMIN_PASSWORD = "Задайте-длинный-уникальный-пароль"
alembic upgrade head
uvicorn app.main:app --reload
```

Локальная база SQLite создаётся в каталоге `backend`. Не добавляйте файл базы, `.env`, реальные токены или ключи в Git.

Полный список переменных окружения с описанием — в [`backend/.env.example`](backend/.env.example). Он лежит в Git, а `.env` с реальными секретами — нет.

### Клиентская часть

В отдельном терминале из корня проекта:

```bash
cd frontend
npm ci
npm run dev
```

Для проверки TypeScript и сборки для развёртывания:

```bash
npm run build
```

### Проверка перед отправкой изменений

Тесты серверной части. Переменные окружения для тестов задаются в `conftest.py`, `.env` не требуется:

```bash
cd backend
pytest
```

Отдельный тест или файл:

```bash
pytest tests/test_xray.py
pytest tests/test_xray.py::test_имя_теста
```

Проверка стиля клиентской части:

```bash
cd frontend
npm run lint
```

## Сервисы и порты

В установленной конфигурации используются FastAPI, Nginx, Xray, а при включении соответствующих функций — AmneziaWG и WARP. Nginx принимает публичный HTTPS-трафик и передаёт протоколы на локальные сервисы. Конкретные адреса и порты могут отличаться в зависимости от настроек панели и конфигурации сервера.

Публичный `/health` предназначен для простой проверки доступности API. Управляющие API требуют авторизации.

### Бесплатный WARP

Во вкладке WARP нажмите «Включить WARP», затем примените готовые правила для
нужных сервисов. Панель использует установленный `cloudflare-warp`, сохраняет
существующую регистрацию либо создаёт бесплатную, задаёт локальный SOCKS5-прокси
и проверяет реальное подключение. При сбое настройки не сохраняются, прежний
режим и порт восстанавливаются. Для обычного WARP лицензионный ключ не нужен.
Необязательный ключ WARP+ находится в дополнительных настройках.

Применение готовых правил автоматически включает режим «По правилам».
Кнопка включения WARP сама по себе не переводит весь трафик на WARP.
Полный туннель сервера доступен в дополнительных настройках; для работы
маршрутов Xray используйте режим «Прокси».

## Безопасность

- Используйте уникальные длинные пароли и секрет `JWT_SECRET_KEY`.
- Храните серверный `.env`, базу данных, резервные копии, приватные ключи и токены отдельно от Git.
- Перед публикацией проверяйте изменения и содержимое коммита на секреты и пользовательские данные.
- Не запускайте скрипты установки из непроверенного источника с правами root.

Архивы `scripts/backup.sh` содержат `.env` с секретами и приватные ключи. Храните их вне репозитория и не прикрепляйте к обсуждениям и запросам на включение изменений.
