# Проверка MTProto на iOS — 6 ноября 2026

Статус: эксперимент, не включён в установку панели и не меняет выдачу подписок.
Основная версия панели остаётся на FakeTLS (`ee`). Эта ветка сохраняет
результаты диагностики и воспроизводимый генератор отдельного `dd`-конфига.

## Что проверено на настоящих устройствах

- iOS 26.6.2, Telegram 13.2: основной FakeTLS-прокси зависал, тогда как
  Android с тем же профилем и Wi-Fi передавал сообщения.
- Сервер принимал только первый TCP-сегмент начального TLS-пакета iPhone:
  1448 байт при объявленной полной длине 1514–1531. Точная причина отсутствия
  продолжения не установлена; это не доказательство ошибки серверного парсера
  или блокировки оператором.
- Временное ограничение MSS до 1200 только для тестового IP и порта результата
  не дало; диагностическое правило удалено.
- Изолированный mtg-multi 1.13.0 с `[secured] enabled = true`, тем же ключом,
  отдельным публичным портом и прежним SOCKS-выходом заработал на iPhone.
  Пользователь подтвердил отправку сообщений как через IPv4, так и через домен.
  Сервер подтвердил активные сессии и двусторонние счётчики трафика.
- Первые попытки dd содержали ошибку в вручную составленной ссылке: к ключу
  был добавлен первый символ доменной части ee-секрета. В этих попытках
  сервер получил SOCKS5 greeting 05 01 00. Это ошибка тестовой ссылки, а не
  подтверждённый дефект Telegram. Исправленная ссылка использует ровно
  16 байт ключа после префикса dd, всего 17 байт/34 hex-символа.

## Как воспроизвести без изменения основного прокси

Вход — приватный staging JSON панели `/var/lib/md-next/app-config/mtproto.json`.
Он содержит `port`, `domain`, `users` и секреты пользователей. Не публиковать.
Профиль pN должен уже присутствовать среди активных пользователей.

```sh
sudo install -d -m 700 /run/md-next-mtproto-ios
sudo python3 experimental/mtproto-ios/render_trial.py \
  --input /var/lib/md-next/app-config/mtproto.json \
  --profile pN --host proxy.example.com \
  --port 8448 --stats-port 10911 \
  --output /run/md-next-mtproto-ios/config.toml --show-link
```

Ссылка выводится только по `--show-link` и содержит секрет. Команду с этим
флагом выполнять в приватном терминале, не в CI и не в общем журнале.
Номера портов — пример; предварительно проверить, что они свободны и
публичный порт разрешён у хостинга. Генератор не меняет firewall, systemd,
основной конфиг или базу и отказывается перезаписывать существующий файл.
Конфиг содержит только выбранного пользователя и создаётся с правами 0600.

Запускать отдельным временным экземпляром закреплённого mtg-multi 1.13.0,
с лимитом времени жизни (в проверке использовался systemd RuntimeMaxSec=600).
Перед запуском от сервисного пользователя выдать ему чтение приватного
конфига и проход в каталог, не делая файл общедоступным. API статистики
остаётся на loopback. После проверки остановить экземпляр и удалить конфиг.

`dd` не маскирует трафик под TLS, в отличие от `ee`; его доступность зависит
от сети. Это проверенный обход для данного iPhone, а не универсальное
исправление причины FakeTLS. Его нельзя незаметно включать всем установкам.
Трафик временного экземпляра учитывается его собственным API статистики;
панельный сборщик 10910 автоматически его не учитывает. Для постоянной
эксплуатации нужна интеграция, а не оставленный диагностический сервис.

## Дальнейшая работа

1. Добавить явный выбор режима FakeTLS/secured с сохранением прежнего значения
   по умолчанию, проверкой ссылок и предупреждением при смене выдачи.
2. Согласованно передавать режим в root helper, конфиг сервиса и клиентские
   ссылки; существующие ключи не перевыпускать.
3. Проверить учёт трафика, отзыв, перезагрузку, откат и оба клиента после
   интеграции. Не переносить временный порт/ключ или частные IP в defaults.
4. Продолжить поиск причины неполного ClientHello при необходимости. Изменение
   режима на dd само по себе эту причину не устанавливает.

В репозитории нет реальных клиентских ключей, ссылок подписок, дампов пакетов
или конфигурации боевого сервера.
