# Испытания 5 ноября 2026 года

Это результаты конкретного стенда, а не обещание производительности на любом VPS.
Рабочий сервер панели 195.78.48.60 и DNS не изменялись.

## Изменения панели

В main через PR [99](https://github.com/tro9n4ik/md-next/pull/99) вошёл выпуск
2.5.11, коммит eb82d3c927e2a90fc3368250c3752729904449c5.
Перед слиянием штатные проверки и проверка секретов завершились успешно.

- В трёх namespace прошли nftables и iptables: DF1352, MSS1340 IPv4 и MSS1320
  IPv6 в обе стороны, повторное применение и удаление правил. Тот же тест
  включён в Linux CI.
- Настоящая блокировка SSH на тестовом VPS закончилась независимым возвратом
  firewall через 180,724 секунды по журналу systemd. Отдельно проверено успешное
  подтверждение со снятием таймера и удалением временного состояния.
- На двух VPS привязанный секрет отклонён на другом machine-id с DecryptionError,
  переносимое представление восстановилось. Использовались синтетические данные.
- Публичные ответы нод проверены тестами на отсутствие адресов и секретов;
  административные маршруты кластера остаются закрыты для subadmin.
- Перенос рабочей панели и установка выпуска на ней не запускались.

## Транспорт Go

Ветка feature/node-transport-go-hardening включает обновлённый main.
Протокол в main и штатный установщик не включён.

На 88.210.35.93: четыре vCPU Common KVM processor с AES, Ubuntu 24.04,
ядро 6.8. Два peer работали в отдельных namespace через veth и настоящие TUN,
MTU1380, AES-128-GCM, портовый слот 20 секунд, drain 15 секунд.
Буферы обоих демонов и iperf3 — 8 МиБ.

Финальный UDP-прогон 120 секунд, задано 300 Мбит/с:

| Показатель | Измерено | Критерий |
|---|---:|---|
| Полученная скорость | 299,90 Мбит/с | Измерение |
| Потери | 0,0334% | ≤0,5% — пройден |
| Наблюдаемые состояния портов | 13 на каждом peer | Ротация — пройдена |
| Ответы ping | 600 из 600 | Измерение |
| Медиана / максимум RTT | 0,3375 / 11,0 мс | Отклонение ≤20 мс — пройден |
| CPU отправителя / получателя | 34,39 / 29,82% одного ядра | ≤15% — **не пройден** |

В этом прогоне не выявлен обрыв туннеля при ротациях. Соседние порты не
повторяются; расчёт согласован между peer и проверен отдельным тестом.

Профиль отдельного 30-секундного прогона показал преобладание системных вызовов:
примерно 81% сэмплов отправителя и 66% получателя. Шифрование занимало около
7% и 10% сэмплов соответственно. Это доли профиля, не процент ядра.
Уже устранены HMAC на каждом пакете, частые вызовы CSPRNG для padding,
очередь между чтением TUN и отправкой, повторные выделения буферов кодека.
Для достижения CPU-критерия требуется дальнейшая работа с системным вводом-выводом
и возможными offload-механизмами; достижение цели пока не заявляется.

На WAN между РФ и Нидерландами прошёл DF1352. Прямой UDP-тест без туннеля
при заданных 300 Мбит/с получил около 69,6 Мбит/с. Приёмку на 300 Мбит/с
для этого маршрута подтвердить не удалось. Ранние замеры с маленьким буфером
iperf3 не используются для приёмки: часть потерь происходила в самом измерителе.
О DPI, невидимости и отсутствии троттлинга выводы не делались.

На промежуточном коммите 478ae08 в Linux CI успешно выполнены vet, race,
fuzz 5 секунд, микробенчмарк, регрессия чтения TUN и namespace-прогон.
Окончательный коммит должен пройти тот же workflow; его статус проверяется
отдельно, успех промежуточного запуска не заменяет финальные проверки.

## Очистка стенда

На обоих VPS остановлены только созданные тестовые службы и iperf3,
удалены тестовые TUN/namespace, ключи и файлы /root/mdnext-network-lab.
Лимиты rmem_max/wmem_max возвращены с 8388608 к исходным 212992.
Временное правило доступа к iperf и отдельный TCP-маршрут с advmss1200 удалены.
На РФ восстановлен исходный файл зеркал apt. dpkg --audit пуст на обоих VPS.

На Нидерландах Xray, WARP и существующий md-next-warp-control остались active.
Пакеты iperf3 и его зависимости оставлены как инструменты стенда; служба iperf3
отключена. Исторические записи systemd не удалялись.

Открытый пункт ТЗ: CPU ≤10–15% одного ядра при 300 Мбит/с. Базовая функциональная
проверка ротации проходит, но весь набор требований производительности пока не закрыт.
