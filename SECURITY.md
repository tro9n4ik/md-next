# Сообщения об уязвимостях

Не размещайте токены, пароли, ключи, базы данных и резервные копии в публичных Issues или Pull Requests.

Если доступна функция GitHub «Report a vulnerability», используйте её для приватного сообщения. Иначе создайте Issue с просьбой предоставить приватный канал связи, без деталей уязвимости и секретов.

В приватном отчёте укажите версию проекта, затронутый компонент и шаги воспроизведения на собственном сервере. Замените реальные адреса, аккаунты и ключи на примеры.

Обновление приложения не заменяет обновления ОС, ограничения доступа, проверку TLS и резервное копирование.
