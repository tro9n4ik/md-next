# Защищённое подключение нод

Новые подключения используют VLESS TCP + Reality с Vision. Приватный ключ создаётся на ноде и не передаётся панели. Панель получает публичный ключ и UUID по HTTPS с одноразовым приглашением. Для отпечатка используется Firefox, цель Reality — www.cloudflare.com:443.

Уже подключённые Trojan/gRPC-ноды сохраняют прежний маршрут до отдельной миграции. Их канал не становится защищённым только от обновления панели.

## Миграция существующей ноды

1. Сохранить конфигурацию Xray ноды и настройки её маршрута в панели.
2. Добавить защищённый вход на отдельном порту, сохранив старый вход.
3. Проверить выход через новый вход с сервера панели, включая DNS, WARP и доступ Telegram.
4. Только после успешной проверки переключить данные ноды в панели; проверить клиентов Xray и AWG.
5. Удалить старый незашифрованный вход после подтверждения результата. При сбое восстановить прежние настройки.

Не запускайте скрипт подключения поверх действующей ноды для миграции: обычная регистрация меняет её конфигурацию и реквизиты. Нужен контролируемый переход с двумя входами.

## Дополнительный путь к нодам через локальный WARP

Если прямой канал между мастером и нодой работает медленно или нестабильно, можно проверить другой путь: мастер → локальный WARP → выбранная нода → интернет. Выходным сервером остаётся нода; клиентские ссылки и её ключи не меняются. Само по себе это не гарантирует ускорение: сначала сравните передачу данных через оба пути.

Режим выключен по умолчанию. В разделе **WARP → Канал к нодам через WARP** нажмите «Подготовить WARP», если локальное подключение ещё не готово. Подготовка устанавливает клиент из [официального репозитория Cloudflare](https://pkg.cloudflareclient.com/), регистрирует бесплатный WARP через выбранную ноду и подключает локальный SOCKS. Поддерживаются Ubuntu 22.04, 24.04 и 26.04 и Debian 12–13. Задание выполняется отдельной ограниченной по времени службой и продолжает работу после закрытия страницы. Маршрут клиентов во время подготовки не переключается.

Нажмите «Проверить канал» и включите тумблер. Перед применением повторно проверяются локальный WARP и выход через выбранную ноду. Состояние хранится в базе, применяется к резервным нодам и сохраняется после перезапуска. Для отмены выключите тумблер: обычный канал восстанавливается, регистрация сохраняется. При ошибке применения выполняется откат настройки и конфигурации.

Существующая переменная `NODE_UPLINK_WARP_PORT` поддерживается для совместимости и для самостоятельно подключённого локального прокси. Пока настройка ещё не сохранена в панели, непустой ненулевой порт включает канал автоматически после обновления. После первого сохранения тумблер имеет приоритет над этой переменной, в том числе при выключении. Адрес прокси закреплён за `127.0.0.1`; допускаются порты от 1 до 65535.

Подготовка сохраняет исходные параметры WARP и изменяемые файлы репозитория в защищённую копию `/var/backups/md-next/uplink-setup-*`. Подтверждённая регистрация повторно не создаётся. Подключённый WARP с другим режимом или портом автоматически не перенастраивается. При ошибке подключения восстанавливаются изменённые параметры и исходное состояние службы; установленный пакет остаётся для повторной подготовки.

Через дополнительный путь идут каналы всех нод, проверки их портов, проверки выхода и управление WARP на нодах. Поэтому резервирование оценивает тот же путь, который используется для рабочего трафика. Прямой выход основного сервера остаётся прямым. Пресеты WARP выбранной ноды работают поверх её канала как прежде; промежуточный WARP не заменяет её выход.

Локальный прокси должен работать независимо от канала Xray, который проходит через него: иначе получится замкнутый маршрут. Для регистрации создаётся отдельное временное подключение к ноде без промежуточного WARP; удаляются только собственные правила регистрации. При отказе прокси доступность нод снижается, и применяются существующие настройки резервирования, включая разрешённый администратором прямой выход. Скрытого обхода прокси в проверке порта нет.

## Индивидуальные выходы клиентов

У каждого клиента есть необязательное назначение `exit_node_id`. Пустое значение сохраняет общий маршрут панели. Назначать и менять выход может только администратор через карточку клиента или при создании подписки. API выбора нод не раскрывает их адреса, секреты и ключи.

Для VLESS, XHTTP, Hysteria 2 и обхода БС сопоставляется серверный email профиля Xray; для AmneziaWG — уникальный адрес пира на входе `awg-in`. Назначение применяется до общих правил выхода, включая WARP, но после индивидуальной блокировки рекламы. Общие запреты добавляются и для закреплённых клиентов. Промежуточный канал `uplink-warp` применяется к нодам независимо от назначения. MTProto использует общий SOCKS-вход и сохраняет общий выход.

Отказ ноды не сбрасывает назначение: соединение закрывается без перехода на прямой выход или другую ноду. Выключенная, отсутствующая или некорректно настроенная нода получает маршрут `block`. Для временно недоступной ноды сохраняется исходящий канал, поэтому после восстановления связи новые соединения возобновляются. Удаление ноды с назначениями запрещено API и внешним ключом; сначала переведите клиентов на другой выход. Обновление схемы оставляет существующим клиентам общий маршрут, сохраняя подписки и ключи.

## Подписи обновлений

Самообновление требует успешных CI и сканирования секретов, а также verification.verified=true от GitHub. Отдельный установщик повторно проверяет подпись заданного SHA до скачивания и выполнения кода. Отсутствие подписи или недоступность проверки блокирует обновление до изменения рабочей панели.

Это проверка подписи GitHub, а не закрепление личного ключа автора. Защита main и обязательное ревью остаются необходимыми. Для выпуска используйте подписанный коммит или подписанный GitHub merge, убедившись, что GitHub показывает Verified.
