# Защищённое подключение нод

Новые подключения используют VLESS TCP + Reality с Vision. Приватный ключ создаётся на ноде и не передаётся панели. Панель получает публичный ключ и UUID по HTTPS с одноразовым приглашением. Для отпечатка используется Firefox, цель Reality — www.cloudflare.com:443.

Уже подключённые Trojan/gRPC-ноды сохраняют прежний маршрут до отдельной миграции. Их канал не становится защищённым только от обновления панели.

## Миграция существующей ноды

1. Сохранить конфигурацию Xray ноды и настройки её маршрута в панели.
2. Добавить защищённый вход на отдельном порту, сохранив старый вход.
3. Проверить выход через новый вход с сервера панели, включая DNS, WARP и доступ Telegram.
4. Только после успешной проверки переключить данные ноды в панели; проверить клиентов Xray и AWG.
5. Удалить старый незашифрованный вход после подтверждения результата. При сбое восстановить прежние настройки.

Не запускайте скрипт подключения поверх действующей ноды для миграции: обычная регистрация меняет её конфигурацию и реквизиты. Нужен контролируемый переход с двумя входами.

## Дополнительный путь к нодам через локальный WARP

Если прямой канал между мастером и нодой работает медленно или нестабильно, можно проверить другой путь: мастер → локальный WARP → выбранная нода → интернет. Выходным сервером остаётся нода; клиентские ссылки и её ключи не меняются. Само по себе это не гарантирует ускорение: сначала сравните передачу данных через оба пути.

Режим выключен по умолчанию. Он требует уже подключённого WARP на мастере с локальным SOCKS-портом. В `backend/.env` задайте `NODE_UPLINK_WARP_PORT` равным этому порту, затем перезапустите backend для загрузки окружения и применения конфигурации. Допустимы только порты от 1 до 65535, адрес закреплён за `127.0.0.1`. Перед изменением сохраните `.env` и рабочий конфиг Xray. Панель не устанавливает и не регистрирует локальный WARP автоматически.

Через дополнительный путь идут каналы всех нод, проверки их портов, проверки выхода и управление WARP на нодах. Поэтому резервирование оценивает тот же путь, который используется для рабочего трафика. Прямой выход основного сервера остаётся прямым. Пресеты WARP выбранной ноды работают поверх её канала как прежде; промежуточный WARP не заменяет её выход.

Локальный прокси должен работать независимо от канала Xray, который проходит через него: иначе получится замкнутый маршрут. При отказе прокси доступность нод снижается, и применяются существующие настройки резервирования, включая разрешённый администратором прямой выход. Скрытого обхода прокси в проверке порта нет. Для отмены очистите `NODE_UPLINK_WARP_PORT` или задайте `0` и перезапустите backend; при ошибке восстановите сохранённые настройки.

## Подписи обновлений

Самообновление требует успешных CI и сканирования секретов, а также verification.verified=true от GitHub. Отдельный установщик повторно проверяет подпись заданного SHA до скачивания и выполнения кода. Отсутствие подписи или недоступность проверки блокирует обновление до изменения рабочей панели.

Это проверка подписи GitHub, а не закрепление личного ключа автора. Защита main и обязательное ревью остаются необходимыми. Для выпуска используйте подписанный коммит или подписанный GitHub merge, убедившись, что GitHub показывает Verified.
