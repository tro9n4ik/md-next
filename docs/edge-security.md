# Защита публичного сайта и панели

Защита дополняет существующую маршрутизацию MD-Next. Она не обеспечивает защиту от блокировки адреса или домена провайдером.

## Что устанавливается

- Публичная библиотека «Кедр Облако»: адаптивная страница, два настоящих небольших документа, без приёма паролей и личных файлов.
- Fail2ban: SSH — шесть ошибок за десять минут, блокировка на пятнадцать минут только SSH; форма входа панели — те же значения, блокировка только `/api/v1/auth/login` через Nginx.
- Nginx: вход — 6 запросов/мин с запасом 8; публичные файлы — 15 запросов/с с запасом 40; известные пути сканеров — 2 запроса/с с запасом 4 на адрес и 4 запроса/с с запасом 8 суммарно. Лимиты соединений соответственно 8, 20 и 4. XHTTP, CDN, API вне формы входа и подписки не ограничиваются этими правилами.
- Krawl: закреплённый коммит `37dce9a535d84d1707c18d6c8f4b68b2ee5d8adf`, отдельный пользователь и виртуальное окружение, SQLite, только `127.0.0.1:5001`. Режим наблюдения: без распространения банов, внешних списков блокировки, AI, бесконечной генерации ссылок и задержек.

Nginx принимает IP из PROXY protocol только от локального stream-прокси. При передаче в Krawl заголовки клиента заменяются. IP за внешним CDN нельзя считать адресом конечного пользователя без отдельной доверенной настройки CDN; VPN-запросы не используются как источник Fail2ban.

## Установка на существующий сервер

Сначала сохраните конфигурацию Nginx и каталог `backend/app/static/fake`. Скрипт дополнительно сохраняет `md-next.conf` в `/root/md-next-security-backups/<дата>/`.

```sh
bash scripts/install-edge-security.sh
nginx -t
fail2ban-client status
systemctl status md-next-krawl
```

Скрипт рассчитан на стандартный Nginx MD-Next. Неизвестную структуру он отклоняет до изменения конфигурации. Изменения повторяемы, конфигурация проверяется перед reload. Версии зависимостей Krawl закреплены в `scripts/krawl-requirements.lock`; фактически установленные версии записываются в `/etc/md-next-krawl/installed-requirements.txt`.

Krawl ограничен 20% CPU, 128 МБ памяти и 32 задачами. При его недоступности только пути сканеров получают 404. Основной сайт, панель, подписки и VPN продолжают работать. Хранение событий — семь дней, журналы Krawl ротируются по 1 МБ; журналы входа Nginx — семь ежедневных архивов.

Таймер `md-next-krawl-guard` раз в пять минут останавливает только наблюдатель, если его данные и журналы превышают 96 МБ либо на диске остаётся меньше 512 МБ. Это порог наблюдения с возможным превышением между проверками, а не файловая квота. Для возобновления сначала проверьте причину и освободите место, затем запустите `md-next-krawl`. Журнал guard доступен через `journalctl -u md-next-krawl-guard`.

## Частная панель наблюдения

Доступ через SSH-туннель, без публикации в Nginx:

```sh
ssh -L 5001:127.0.0.1:5001 root@SERVER
```

Откройте `http://127.0.0.1:5001/_krawl-admin`. Пароль хранится на сервере в `/etc/md-next-krawl/environment`; файл доступен только root и группе отдельной службы. Не публикуйте его в отчётах. Данные подозрительных запросов могут содержать введённые сканерами строки и заголовки; доступ к SQLite и логам закрыт от остальных пользователей.

## Проверка и отключение

```sh
python3 scripts/test-security.py
fail2ban-client status sshd
fail2ban-client status md-next-panel
systemctl show md-next-krawl -p MemoryCurrent -p MemoryMax
```

Для отключения наблюдения: `systemctl disable --now md-next-krawl`. Для удаления блокировки формы входа: `fail2ban-client set md-next-panel unbanip IP`. Не останавливайте весь Fail2ban ради разблокировки одного адреса.

Для полного отката восстановите сохранённый `md-next.conf`, удалите `md-next-security.conf` из `conf.d`, отключите jail `md-next-panel` в `jail.d/md-next-security.local`, затем выполните `nginx -t`, reload Nginx и `systemctl restart fail2ban`. SSH jail можно оставить включённым. Публичные файлы восстановите из резервной копии.
