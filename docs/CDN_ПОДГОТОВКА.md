# Подготовка CDN

Статус: каркас, выключен. Наличие CDN само по себе не гарантирует доступ в сети с белыми списками.

Подготовлен дополнительный VLESS XHTTP/TLS-профиль для Happ и v2rayNG. Он использует UUID существующего XHTTP/TLS-профиля, его ограничения подписки, счётчики трафика и общий выход через выбранную ноду. Vision и Reality для этого профиля не используются.

Администратор может читать и сохранять домен через `GET` и `PUT /api/v1/cdn`. Домен без протокола и пути сохраняется как черновик. Включение до проверки ресурса провайдера отклоняется; новые профили в действующих подписках не появляются.

Режим клиента — `packet-up`. Путь берётся из действующей настройки XHTTP/TLS: изменение пути одновременно влияет на origin, поэтому отдельный произвольный путь CDN не создаётся. `make_cdn_link(..., preview=True)` позволяет получить тестовую ссылку без включения массовой выдачи.

Для следующего этапа потребуются:

- CDN-ресурс в собственном аккаунте, пользовательский домен и сертификат TLS на стороне CDN.
- HTTPS-origin панели с правильными SNI и Host. Публичный домен CDN должен обслуживаться ресурсом, а не указывать напрямую на VPS.
- Передача GET и POST без кэширования, сохранение пути и query string, отключение буферизации и лимитов, мешающих XHTTP.
- Проверка полного туннеля через CDN: HTTPS, длительная загрузка, ограничения подписки, общий выход ноды, доступ из ограниченной сети.

Серверный тест origin без CDN подтверждает только работу локального Nginx → XHTTP → выход. Доступность адресов провайдера в белых списках и совместимость его прокси проверяются отдельно. Тестировать чужие домены или подменять SNI стороннего сервиса не требуется.

Основа транспорта: [официальная документация XHTTP](https://xtls.github.io/en/config/transports/splithttp.html).
