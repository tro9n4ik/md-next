# Обновление панели

Откройте **Настройки → Обновление панели**, нажмите «Проверить обновления», затем «Обновить панель». Установка требует подтверждения администратора. Сборка берётся только из ветки `main` официального репозитория `tro9n4ik/md-next`; выбранный коммит закрепляется до конца операции. Оба workflow, `ci.yml` и `secrets.yml`, должны завершиться успешно. Проверка завершения CI требует доступа к GitHub Actions выбранного репозитория.

Для приватного репозитория введите токен чтения в соответствующем поле либо настройте `MDNEXT_GITHUB_TOKEN` в серверном `backend/.env` с правами 0600 и перезапустите backend. Токен из формы живёт только в памяти браузера и временном файле запроса с правами 0600 на сервере; файл удаляется при начале фонового процесса. Токен не включается в командную строку или ответ API. После открытия репозитория токен можно удалить.

## Что происходит

1. Отдельный процесс systemd скачивает конкретный коммит, создаёт новое виртуальное окружение на том же базовом Python и выполняет `npm ci` и сборку интерфейса. Текущая панель продолжает работать.
2. Сохраняются файлы приложения с `.env`, SQLite-база и конфигурации Xray/AWG. Каталоги копий и окружений не дублируются. Копия находится в `/opt/md-next-update-backup-ДАТА-ВРЕМЯ`, каталог доступен только root.
3. Backend останавливается, база повторно сохраняется согласованным снимком, заменяется код и активируется новое окружение. Выполняются миграции и запускается новая панель.
4. Проверяется API `/health`, состояние backend/Xray/Nginx и неизменность идентификаторов клиентов. После успеха сохраняется установленный коммит; интерфейс предлагает перезагрузить страницу.

Ошибка подготовки не меняет текущую установку. При ошибке после начала применения восстанавливаются прежние файлы, база, окружение и конфигурации; выполняется проверка запуска. Если откат не завершился, интерфейс сообщает об этом и показывает путь сохранённой копии. Подробный локальный лог: `/var/lib/md-next/updates/update.log`, права 0600.

Обновляется приложение MD-Next; установщик ОС, переустановка Xray/AWG, сертификатов и изменение systemd-юнитов не запускаются. Новая версия backend может перестроить конфигурацию VPN при запуске, поэтому возможен краткий перерыв соединений. Обновление не является резервной копией всего VPS, не переносит сервер на другую ОС и не защищает от отключения питания или отказа диска во время замены файлов. Копии находятся на том же диске: храните внешнюю копию важной установки.

Фоновый процесс не зависит от HTTP-соединения и продолжает работу после закрытия вкладки. Повторная установка во время действующей операции блокируется. Копии и старые окружения автоматически не удаляются; контролируйте свободное место на диске.
