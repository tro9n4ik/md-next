Порядок: завершить проверки публикации, затем подписи обновлений и защищённый канал нод, после этого реальные сетевые проверки. Не включать перехват DNS или блокировку QUIC для всех пользователей без проверки влияния на соединения.

Двухфакторную аутентификацию аккаунта GitHub и аппаратный ключ настраивает владелец аккаунта. Защита ветки должна требовать ревью и запрещать force-push; порядок выпуска при этом нужно перевести на Pull Requests.


## Проверка защищённого канала

9 октября на отдельном VPS с Ubuntu 24.04 и Xray 26.3.27 проверены два изолированных процесса Xray на локальных портах: HTTPS-запрос через VLESS Reality с Vision и Firefox выполнен, неверный публичный ключ отклонён.

На действующей панели установлена версия 2.4.14 из проверенной ветки. Обе ноды мигрированы через параллельный защищённый вход с резервной копией; идентификаторы нод и входящие профили клиентов сохранены. Выходы NL и DE проверены через реальные диагностические порты панели. После отключения старых служб повторно проверены Reality, WARP и HTTPS-доступ к API Telegram через обе ноды. API состояния панели сообщает, что VPN-службы и Telegram-бот работают. Эти проверки не заменяют тесты с телефона.

В отдельном Linux-процессе установщик отклонил неподписанную версию до первого вызова команд скачивания или выполнения. Полный backend-набор после основных изменений: 383 успешных теста, 17 пропущенных; дополнительные проверки подписи и регистрации запускаются отдельно.

Для изменений 2.4.15 полный прогон на тестовом Ubuntu VPS: 424 успешных теста; на Windows: 392 успешных и 19 пропущенных Linux-проверок. Дополнительные проверки матрицы отпечатков и минимального запроса HandlerService: 12 успешных. На том же VPS пройден полный цикл установки с backend от md-next, входа, копии, отмены удаления, удаления с сохранением данных и полной очистки. Чужое правило fwmark и маршрут сохранились; временное правило теста затем удалено.

Локальная матрица отпечатков на production-сервере не дала успешного соединения ни с Chrome, ни с Firefox (curl 35). Это не воспроизводит мобильную сеть и не устанавливает причину исходного сбоя. Работа Firefox и всех четырёх профилей Happ подтверждена пользователем отдельно.
