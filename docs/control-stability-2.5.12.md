# Устойчивость сети и идентичности установки — 2.5.12

Идентификатор HKDF сохраняется в `/var/lib/md-next/host.key` (0600). При первом запуске копируется прежний machine-id без изменения соли v2; при отсутствии пригодного machine-id создаётся случайный сид. Публикация атомарная, параллельные процессы принимают один файл. Повреждённый файл или ссылка приводят к отказу, а не молчаливой смене ключа. Миграция 0022 сохраняет идентичность; опубликованная 0021 не изменена.

В контейнере необходимо сохранять volume `/var/lib/md-next` вместе с базой и исходным JWT_SECRET_KEY. Не удаляйте host.key при пересоздании контейнера. При обновлении существующей установки ключ нужно впервые сохранить до смены machine-id: новый файл не восстанавливает уже утраченный идентификатор. Штатный установщик оставляет каталог состояния root:root 0755, файл передаёт службе md-next с режимом 0600. Root-помощник также читает его. Логические резервные копии сохраняют переносимость через существующее перешифрование секретов.

Метаданные событий нод ограничены публичной схемой; дополнительный фильтр действует перед записью в журнал. В текущем backend нет WebSocket-шины, описанной в исходном плане: проверяется реальный журнал событий.

MSS применяется в mangle: nftables priority −150, iptables/ip6tables — вставка в начало FORWARD, до прежних RETURN. Обрабатываются только интерфейсы AWG; чужие правила не удаляются. Повторное применение не создаёт дубликатов.

Страховка отката остаётся независимым systemd-таймером. HTTPS-проверка контроллера выполняется отдельно: DNS на исходном сервере ограничен дочерним процессом, новый VPS соединяется с числовым IP, сохраняя TLS SNI и проверку сертификата имени. Общий бюджет дочерней проверки — 2 секунды; неуспех запрещает подтверждение. HTTP 200 без JSON состояния ok недостаточен. Проверка шлюза вместо контроллера не используется, поскольку она не подтверждает доступность панели.

Изолированный серверный тест блокировал исходящие соединения namespace: probe завершился за 2,167 с, затем при опущенном link страховка самостоятельно восстановила firewall через штатный таймер 180 с. Команда для повторения: `sudo python3 scripts/test-controller-latch.py --run`. Тест не меняет firewall хоста.

## Проверки

Полный локальный backend: 895 прошли, 85 пропущены; дополнительный набор после уточнения проверки HTTPS: 11 прошли, 1 POSIX-пропуск на Windows. Сборка интерфейса, линтер, 50 frontend-тестов и согласованность версии пройдены. На отдельном RF VPS успешно проверены пересоздание контейнера с сохранённым volume и изменённым machine-id, nftables и iptables MSS в обе стороны IPv4/IPv6, DF-пакеты, повторное применение и очистка правил. Контейнеры, сети и временный образ удалены.

Повторяемый стенд: `sudo python3 scripts/test-control-docker.py --run`. Создаёт временный локальный образ Python, проверяет пересоздание контейнера с тем же томом и другим machine-id, затем две Docker-сети и три контейнера. Проверяет MSS в обе стороны IPv4/IPv6 и DF-пакеты, повторное применение и удаление правил. Удаляет собственные контейнеры, сети, образ; восстанавливает исходные forwarding sysctl. Запускать только на выделенном стенде. Без --run печатает план.
