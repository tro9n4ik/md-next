# Импорт маршрутизации Happ — 2.5.13

## Подтверждённые наблюдения

Действующая панель 2.5.11 возвращала routing: happ://routing/onadd/..., но кодировала символы Base64 через percent-escaping. Содержимое после onadd не проходило прямую строгую проверку Base64. Локальные тесты ранее сами делали unquote и поэтому не обнаруживали это отличие. Пользователь сообщил, что на Android профиль MD-Next DNS отсутствует.

Официальный конструктор https://routing.happ.su/en формирует URL-safe Base64, заменяет + и / на - и _, удаляет завершающие =. Исправленный генератор повторяет этот формат. Документация https://github.com/HappDev/happ_su/blob/main/dev-docs/routing.md разрешает передачу ссылки как HTTP-заголовком routing, так и отдельной строкой в теле подписки.

Для User-Agent с Happ ссылка теперь дополнительно стоит первой строкой декодированного Base64-тела, перед VPN-профилями. Заголовок routing сохранён; routing-enable: true явно включает функцию. Для остальных клиентов состав тела прежний. При недоступной подписке или отсутствии профилей служебная строка в тело не добавляется.

## Проверка на устройстве

После установки выпуска обновить существующую подписку в Happ и открыть маршрутизацию именно этой подписки. Ожидается профиль MD-Next DNS. Изменения маршрутизации применяются после переподключения. Приложение отдельно загружает GeoIP/GeoSite; ошибки их загрузки нужно отличать от отсутствия импортированного профиля. Ссылки на geo-файлы этим исправлением не меняются.

Тесты подтверждают формат и выдачу панели; успешный импорт в конкретной сборке Android требует проверки на устройстве. Старый DNS bootstrap после переезда был отдельной ошибкой и уже исправлен на рабочем сервере.
