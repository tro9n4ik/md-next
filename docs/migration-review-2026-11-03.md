# Проверка переезда MD-Next — 3 ноября 2026

Подготовлены локальные изменения в ветке `fix/migration-diagnostics-and-preparation`, исходная сборка `9e58cd2` (2.5.1). Установщики и команды управления VPS не запускались, серверы и DNS не изменялись. На момент этой локальной проверки изменения ещё не были опубликованы и развёрнуты.

## Исправления по пяти пунктам

1. **Ошибки.** Добавлен фиксированный каталог `MIG_*`, этап и код завершения процесса. Веб-интерфейс показывает причину сбоя вместо общего сообщения. Ответы валидации больше не возвращают исходные значения ошибочно введённых паролей. Неизвестные исключения и произвольный stderr не выводятся в браузер.
2. **Мониторинг.** Добавлены структурированные сообщения целевого VPS и шагов установщика, журнал последних 80 событий и время последнего сообщения. Поток принимает только известные коды, без произвольных строк и секретов. Подробности остаются в закрытых root-журналах. Убрано противоречивое сообщение об успешном запуске после ошибки; отдельно показывается сбой опроса состояния.
3. **Обновление до установки.** Целевой драйвер проверяет ОС, архитектуру, память, диск и порты, ждёт освобождения apt/dpkg, обновляет ОС. Таймеры apt временно приостанавливаются с восстановлением прежнего состояния. Если нужна перезагрузка, установка блокируется до ручной перезагрузки; проверяется смена boot ID. Автоматического перезапуска нет.
4. **Сбой `awg0.conf`.** В изолированной установке разделение прав допускает отсутствие рабочего AWG-конфига и создаёт только пустой приватный черновик. Он не применяется к сети. Обычная рабочая установка по-прежнему требует полноценный файл. Начальный пароль в staging не печатается. Повторная подготовка разрешается только для подтверждённой своей установки той же сборки без восстановленных клиентов.
5. **Проверка остальных путей.** Просмотрены API, UI, SSH-операции, установщик, формат комплекта, восстановление, проверка, активация, отмена, блокировки и документация. Дополнительно исправлены перечисленные ниже дефекты.

## Дополнительные найденные дефекты

- Хэш одного SQLite `.db` не учитывал изменения в WAL. Проверка перед активацией теперь использует согласованный снимок, учитывает конфигурации и сертификаты, а также отклоняет время проверки из будущего.
- Неудачный повторный импорт мог сохранить старое разрешение `verify`. Оно удаляется до первых изменений; журнал незавершённого импорта блокирует проверку и активацию.
- Возобновление VPN при ошибке остановки служб могло привести к записи поверх активной базы. Восстановление теперь проверяет остановку до замены файлов.
- Отмена не удаляла добавленные импортом конфигурации, отсутствовавшие в исходной целевой установке. Теперь это делает ограниченный журнал путей. Отмена повторяема после успешного отката, если возобновление источника не удалось.
- Мастер позволял финальную синхронизацию после неполной подготовки. Теперь требуется отметка успешной проверки, совпадающая с привязкой именно этого VPS.
- Ошибки запуска служб могли игнорироваться при активации/возобновлении. Теперь неуспешный запуск прерывает этап.
- Неиспользуемая пробная зашифрованная копия удерживала RAM перед созданием финальной. Она освобождается. Добавлена проверка памяти перед расшифровкой/восстановлением на цели; защитный порог источника не снижался.
- Снимок SQLite мог неограниченно ждать конкурентных записей. Добавлен предел 60 секунд.
- Остаточные файлы с учётными данными не очищались, если `job.json` отсутствовал. Очистка больше не зависит от него. Повреждённый статус отображается как ошибка, а запускающаяся служба не объявляется прерванной.
- Папки резервирования разделения прав могли столкнуться при двух вызовах в одну секунду. Теперь имена уникальны.
- Проверка домена финального переноса пропускала некоторые некорректные адреса. Добавлена проверка меток/IDNA и запрет IP и localhost.
- Атомарные записи комплектов и служебных маркеров теперь сбрасываются на диск перед дальнейшими действиями.
- Установщик создавал предсказуемый лог в `/tmp`. Теперь используется уникальный root-only журнал в `/var/log`.

## Выполненные проверки

- Backend: 75 целевых тестов прошли, 7 проверок пропущены из-за Windows/прав на симлинки и требований Linux. Проверены создание/декодирование комплектов, восстановление и отмена, WAL, изменение конфигураций, ошибки API без утечки паролей, поток событий, блокировки apt, ожидание перезагрузки, черновик AWG и очистка временных учётных данных.
- Frontend: все 47 тестов прошли, включая отображение ошибки и журнала VPS. TypeScript, production-сборка Vite и lint прошли.
- Синтаксис всех shell-скриптов проверен GNU Bash (`-n`); Python-файлы скомпилированы без ошибок.
- Проверка согласованности версии/документации/демо-материалов и `git diff --check` прошли.

Полная backend-suite вне затронутых компонентов не запускалась. Проверки с реальными systemd/apt/SSH на Linux VPS намеренно не выполнялись.

## Пределы проверки и следующий запуск

Сквозное испытание на Linux VPS не выполнено: пользователь прямо запретил установку и перенос без него. Локальные проверки не доказывают работу внешних TCP/UDP-портов, MTProto, AWG, WARP и отката при обрыве реального SSH. Перед продуктивным переключением всё ещё нужен пробный перенос и внешние тесты всех используемых протоколов.

Частичная установка, оставшаяся от старого мастера, не содержит нового root-маркера подготовки. Она намеренно не подхватывается автоматически: её нужно отдельно проверить и согласовать дальнейшее действие. Не создавайте маркеры вручную и не переписывайте `DEPLOYED_COMMIT` для обхода проверок. Для использования исправленного мастера нужна опубликованная проверенная сборка и согласованное обновление; сейчас ничего из этого не выполнялось.

Ранее вручную остановленные на новом VPS таймеры `apt-daily.timer` и `apt-daily-upgrade.timer` требуют возврата после будущего согласованного завершения работ. Эта локальная доработка их не меняла.
