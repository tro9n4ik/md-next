# KedrLink: управляющий канал нод

KedrLink — отдельный Go-агент управления. В форме «Добавить ноду» выбирается
стандартный канал либо **KedrLink — Go-агент (экспериментальный)**.
Это выбор для одной новой или повторно подключаемой ноды. Пользовательский
VPN-трафик в обоих случаях передаёт существующий Xray (VLESS Reality для новых
установок). Выбор не меняет транспорт других нод и не переключает их автоматически.

## Регистрация и связь

Тип управляющего канала записывается в одноразовое приглашение. Установщик
получает его из панели; при регистрации панель сверяет значение, а для KedrLink —
версию управляющего протокола `1`. Несовпадение откатывает использование токена.
Старые приглашения, вызовы API и существующие записи получают `xray`.
Администратор видит выбранный канал в карточке ноды. Субадмину новые поля,
учётные данные и управляющие операции не выдаются.

Нода устанавливает **исходящее HTTPS-соединение** с панелью, проверяя обычную
цепочку сертификатов. Дополнительный входящий порт не нужен. Это первая
реализация управления; экспериментальный UDP-кодек `mdnt` остаётся отдельным
loopback-экспериментом и не используется для этого HTTPS-канала.

Отдельный случайный 256-битный ключ выдаётся при регистрации один раз. Панель
хранит только SHA-256 ключа, нода — файл конфигурации с правами `0600`.
Ключ привязан к ID ноды, не является JWT администратора и не подходит к остальным
API. Повторная регистрация меняет ключ; возврат на стандартный канал отзывает его.
Перенаправления HTTP запрещены, ошибки и журналы агента не содержат ключа.

## Версия 0.1.0

Агент опрашивает панель каждые 15 секунд. Ошибки соединения включают задержку
повторной попытки от 1 до 60 секунд. Один HTTP-запрос ограничен 10 секундами,
ответ — 8 КиБ. Панель сохраняет версию агента, время последней связи и uptime.
Нет связи более 60 секунд — канал считается недоступным. Это отдельный статус,
который не меняет статус VPN и не запускает переключение клиентского маршрута.

Кнопка «Проверить агент» создаёт запрос `status` с ID и сроком 60 секунд.
До завершения допускается только один запрос на ноду; повторное нажатие возвращает
тот же запрос. Агент подтверждает его при следующем обмене. Повторное подтверждение
безопасно, а просроченное или чужое не завершает команду. В версии 0.1.0 поддерживается
только чтение состояния: shell, обновление конфигурации и другие изменяющие команды
API не принимает.

## Установка и обслуживание

При выборе KedrLink установщик собирает агент из исходного кода **этой панели**.
Для Linux amd64/arm64 скачивается Go 1.27.3 с проверкой закреплённой SHA-256.
Исходник и SDK находятся во временном каталоге; после установки он удаляется.
Стандартный вариант не скачивает Go и не устанавливает агент.

Файлы выбранной ноды:

- `/usr/local/bin/kedrlink-agent` — исполняемый файл;
- `/etc/md-next/kedrlink-agent.json` — закрытая конфигурация;
- `kedrlink-agent.service` — отдельный systemd-сервис.

Перед стартом сервиса выполняется реальный авторизованный HTTPS-обмен `-once`.
Сервис получает только права, необходимые для чтения конфигурации и исходящего
соединения. Он не меняет сетевые маршруты, firewall и конфигурацию Xray.
Для возврата на стандартный вариант создаётся новое стандартное приглашение
и нода подключается повторно; её сервис KedrLink останавливается.

Миграция `0023_node_transport` добавляет поля без изменения прежних подключений.
Логические резервные копии предыдущих схем (0019–0022) дополняются стандартным
каналом при восстановлении. Восстановление копии не возвращает старые ключи
KedrLink и незавершённые команды: агентам нужны новые приглашения. Панель
показывает это в предварительном просмотре восстановления и в карточке ноды.
Откат миграции блокируется, пока есть записи экспериментальных нод или приглашений:
сначала нужно перевести/удалить их, чтобы старый код не потерял различие каналов.

## Проверка перед выделенной нодой

Unit-тесты проверяют авторизацию, ограничения ролей, ротацию ключей, таймауты,
повторные/просроченные подтверждения и миграцию старой БД. Интеграционный тест
`backend/tests/test_kedrlink_e2e.py` запускает настоящий Go-процесс против FastAPI
по TLS с отдельным тестовым CA и проверяет полную цепочку команды и SIGTERM.
Для запуска задаётся `MDNEXT_TEST_KEDRLINK_BINARY` с путём к Linux-бинарнику.

На выделенной ноде отдельно предстоит проверить полный установщик, systemd,
реальный сертификат панели, временную потерю сети и повторное подключение.
Боевые установки в ходе разработки не обновляются.
