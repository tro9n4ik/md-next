# Продолжение ТЗ по стабильности и безопасности

База для продолжения — `main` после PR [№93](https://github.com/tro9n4ik/md-next/pull/93), коммит `5c5a05c`, версия **2.5.6**. Все 14 проверок GitHub для PR прошли.

## Уже в main

- **П1.2** — WAL, ожидание блокировок SQLite и проверка внешних ключей.
- **П1.1** — лимиты регистрации нод и защита от перебора токенов.
- **П1.3** — шифрование секретов нод, миграция `0020` и восстановление логических копий с `0019`.
- **П2.2** — таймауты служебных команд Fail2ban, наблюдателя и самообновления.
- **П2.3** — снятие клиентских привязок и переключение общего выхода при удалении активной ноды.

## Осталось пять пунктов

1. **П2.4. Данные нод у субадминистраторов.** Проверить ответы `/clients`, `/client-groups`, страницы подписок и индивидуальный выход клиента. Сравнить ответы администратора и субадминистратора, проверить внутренние адреса, порты, ключи, идентификаторы выходных нод и пути в ошибках. Если утечка подтверждается, добавить регрессионный тест и закрыть её.
2. **П2.1. MTU и MSS clamping.** На Linux-стенде сравнить PMTU, пропускную способность TCP и успешность TLS с правилом и без него. Использовать `iperf3`, тестовый HTTPS и `ping -M do`. При подтверждённом эффекте добавить идемпотентное правило для `awg0` и `mdawg`, согласовать источник MTU и проверить установку, самообновление и удаление.
3. **П3.1. Ложный офлайн.** Проверить опрос в `Metrics.tsx` и `NodesManager.tsx`. Различать ошибку связи с панелью и ответ панели об офлайне ноды. Проверить повторные запросы с ограниченной экспоненциальной задержкой, отметку устаревших данных и порог последовательных ошибок. Покрыть выбор состояния тестом `node --test`.
4. **П3.2. Безопасность переезда панели.** Проверить сценарии миграции, SSH и сборки архива. Требуются проверка отпечатка до передачи учётных данных, закрытый временный каталог с очисткой, шифрование архива до записи и передачи, а также передача секретов вне аргументов команд.
5. **П3.3. Негативные тесты помощника.** Проверить `privileged-helper.py` на пробелы, переводы строк, `..`, ведущие дефисы, чрезмерную длину, нестроковые значения, неизвестные операции и пустые списки. Править рабочий код только при воспроизводимом обходе.

## Проверки на Linux-стенде

Для опубликованного пакета остаётся проверить права файлов SQLite `-wal` и `-shm`, определение адреса за Nginx после обновления, таймауты реальных служб Fail2ban и systemd, восстановление старой копии с нодами и реальное переключение клиентского трафика на резервную ноду.

Начать с **П2.4**, в отдельной ветке от актуальной `main`. Сначала подтвердить замечание и зафиксировать результат. Для подтверждённой проблемы добавить тест, который падает до правки, и подготовить отдельный небольшой PR. Для публикации использовать русский язык и аккаунт владельца репозитория.

Перед PR прогнать backend `pytest`, `pip-audit -r requirements.txt`, frontend `npm run build`, `npm run lint`, `npm test`, `npm audit`, проверку согласованности выпуска и `bash -n` для каждого `scripts/*.sh`. При изменении поведения обновить версию, README, CHANGELOG и демонстрационные скриншоты. В отчёте указать исходное замечание, результат проверки с файлом и строкой, изменения, тесты и ручную проверку.
