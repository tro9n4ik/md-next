# Исправления сети и подписок MD-Next

Текущая основная ветка также содержит сроки подписок и месячные квоты. Её
сетевой скрипт требует уже установленную миграцию `0010_client_limits` и файлы
учёта ограничений. Он останавливается до изменения файлов, если их нет.
Для отдельного сетевого исправления старой установки без миграций используйте
проверенный коммит `b603fc4d6955de7247a23e59ef20f9e91fda6ad7` в отдельном каталоге:

```bash
git checkout b603fc4d6955de7247a23e59ef20f9e91fda6ad7
```

Для новых сроков и квот требуется полное обновление панели, описанное в README.
Следующие инструкции относятся к сетевому патчу и не заменяют это обновление.

Исправления маршрутизации из PR №4 вошли в основную ветку. Дополнительное
исправление генерации XHTTP Reality убирает несовместимый режим Vision
из клиентской ссылки и серверного списка клиентов. Vision применяется только
к Reality TCP. Настройка отпечатка браузера остаётся на выбор администратора.

## Исправления

- Выход клиентского трафика задаётся точным тегом выбранного узла.
  Переключение на резервный узел и возврат выполняет служба наблюдения;
  дополнительный балансировщик `leastPing`/`burstObservatory` удалён.
- WARP в режиме `all` становится выходом по умолчанию. Пользовательские
  правила маршрутизации обрабатываются раньше общего маршрута.
- Диагностические SOCKS-входы закреплены за конкретными узлами. Режим `keep`
  сохраняет выбранный маршрут при недоступности узла. Ручной прямой выход допустим.
- Определение домена HTTP/TLS/QUIC с `routeOnly` позволяет применять доменные
  правила к соединениям, переданным браузером по IP, без замены назначения.
- SNI Reality TCP согласуется с таблицей Nginx. Существующие записи сохраняются,
  домен панели не перехватывается. Ошибка проверки `nginx -t` вызывает откат.
- PROXY-заголовок Reality отправляется только локальной маскирующей заглушке
  `127.0.0.1:8080` и её аналогам localhost/IPv6. Для внешнего адреса он отключён.
  Другой сервер маскировки, требующий PROXY-заголовок, нуждается в отдельной настройке.
- Happ получает `DnsHosts` для начального разрешения имён настроенных DoH-серверов.
- Неизменившаяся активная конфигурация Xray не вызывает перезапуск.
  При ошибке применяется прежняя конфигурация.
- После отката транзакции базы восстанавливаются прежние параметры сервисов,
  чтобы их UUID и ключи соответствовали сохранённым данным.
- Повторная регистрация узла обновляет пароль Trojan в Xray. Переключение
  состояния узла применяет конфигурацию с откатом при ошибке.
- Проверки узлов запускаются после создания диагностических входов.
- **XHTTP Reality не получает `flow=xtls-rprx-vision`** ни в ссылке подписки,
  ни в серверном профиле. Reality TCP сохраняет выбранный режим XTLS.

## Проверки и границы результата

Регрессионные тесты проверяют маршруты, генерацию подписок, соответствие
клиентских и серверных профилей, проверку совместимости и автоматический откат.
Сквозные тесты Xray выполняются, когда `xray` и `curl` доступны в PATH;
проверки настоящего Nginx пропускаются при его отсутствии.

При диагностике установленного Xray 26.3.27 локальные HTTPS-проверки прошли
для Reality TCP, XHTTP Reality, XHTTP TLS и Hysteria 2. После исправления XHTTP
пользователь подтвердил работу всех четырёх профилей в Happ 4.6.0.

Причина остановки отдельных TLS-соединений с отпечатком Chrome не установлена.
Работа с Firefox и позднее успешное подключение Hysteria 2 сами по себе
не доказывают устранение сетевой нестабильности. Принудительная замена
отпечатка браузера в генераторе не вводится.

## Обновление существующей установки

Для сетевого патча используйте отдельную копию репозитория вне каталога
работающей панели. На сервере с доступом к репозиторию:

```bash
git clone https://github.com/tro9n4ik/md-next.git /root/md-next-network-fix
cd /root/md-next-network-fix
sudo python3 scripts/apply-network-fix.py --app-dir /opt/md-next --check
sudo python3 scripts/apply-network-fix.py --app-dir /opt/md-next --apply
```

Скрипт обновляет только серверные файлы из `NETWORK_FIX_MANIFEST.json`.
Это не полное обновление интерфейса и остальных файлов проекта.
Он принимает известные хеши исходной версии, PR №4 и отдельного исправления
XHTTP. Неизвестные изменения останавливают обновление **до изменения файлов**.
Не обходите проверку: сначала сопоставьте версии.

Перед применением проверяются конфигурации Nginx и Xray. Скрипт создаёт
резервную копию исходников, конфигураций, `.env` и целостную SQLite-копию базы
в `/var/backups/md-next/network-fix-...` с закрытым доступом.
Панель кратковременно останавливается, перезапуск Xray разрывает текущие VPN-сессии.
После обновления проверяются `/health`, состояние и конфигурация Xray,
а также соответствие основного маршрута выбранным настройкам.

При ошибке восстанавливаются исходники и конфигурации. Рабочая база данных
и `.env` при откате не заменяются. Новые зависимости и миграции для сетевого
патча не нужны. Настройка NAT AmneziaWG им не изменяется.

Обновите подписку в приложении и переподключите выбранный профиль после применения.
Для диагностики без изменения настроек:

```bash
sudo /opt/md-next/backend/venv/bin/python scripts/diagnose-network.py --probe
```

При другом пути установки замените `/opt/md-next`. Отчёт выводит выбранные
поля конфигурации без закрытых ключей, паролей, UUID и ссылок подписок.
Флаг `--probe` выполняет два HTTPS-запроса через SOCKS Xray.

## Откат

Скрипт печатает точную команду восстановления. Общий вид:

```bash
sudo python3 scripts/apply-network-fix.py \
  --app-dir /opt/md-next \
  --rollback /var/backups/md-next/network-fix-ДАТА
```

Резервные копии содержат секреты и должны оставаться на сервере.

## Проверка в разработке

```bash
cd backend
pytest -q
```

Тесты используют временные данные и подменяют управляющие вызовы сервисов.
Сквозные тесты создают ключи и сертификаты во временных каталогах и не требуют
конфигураций действующей установки.
