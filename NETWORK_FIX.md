# Исправления сети MD-Next

Это патч к проекту из архива `md-next-main (6).zip`, исходный commit:
`819ae201366b38c04265998d1302b7278a133dfd`.

## Что исправлено

- Выход клиентского трафика задаётся точным тегом выбранной ноды. Убран второй
  механизм переключения через `leastPing`/`burstObservatory`: он зависел от
  случайного времени проверок после перезапуска и сопоставлял теги по префиксу
  (`node-1` мог совпасть с `node-10`). Failover/failback продолжает выполнять
  существующий watchdog с прежними настройками, приоритетами и порогами.
- WARP в режиме `all` становится выходом по умолчанию даже при выбранной ноде.
  Явные пользовательские правила по-прежнему выполняются раньше общего маршрута.
- Диагностические SOCKS-входы остаются закреплёнными за конкретными нодами.
  Режим `keep` не переключает выбранную недоступную ноду на прямой выход.
  Ручной выбор прямого выхода остаётся допустимым.
- Добавлен sniffing HTTP/TLS/QUIC с `routeOnly`: доменные правила могут работать,
  когда браузер передал IP. Исходное назначение соединения не заменяется.
- Перед запуском/применением Reality TCP его SNI согласуется с таблицей Nginx.
  Старые записи сохраняются. Домен, занятый панелью или другим сервисом,
  не перехватывается. Изменение проверяется через `nginx -t`, при ошибке
  файл восстанавливается. Это не изменяет адреса или ключи клиентских профилей.
- PROXY-заголовок к Reality target отправляется только для локальной заглушки
  установщика `127.0.0.1:8080` (и localhost/IPv6-аналогов). Для внешнего target
  он выключен. XHTTP Reality использует ту же логику. Если у вас собственный
  PROXY-speaking target на другом порту, этот патч требует отдельной адаптации.
- Happ получает `DnsHosts` для заданных DoH-серверов: начальный DNS-запрос имени
  самого DNS-сервера не должен зависеть от уже работающего DoH. Сохранённые
  DNS-параметры не заменяются.
- Одинаковая активная конфигурация Xray не вызывает перезапуск и разрыв сессий.
  Ошибка перезапуска восстанавливает файл и запускает прежнюю конфигурацию.
- При ошибке применения профилей после отката БД повторно применяются прежние
  параметры сервисов. В частности, сбой AWG после успешного применения Xray
  больше не оставляет Xray с UUID/ключами, не соответствующими базе.
- Повторная регистрация ноды обновляет её пароль в Xray; включение/выключение
  ноды применяет конфигурацию и откатывает изменение при ошибке.
- API протоколов возвращает Flow. Watchdog начинает проверки после первичного
  создания диагностических входов. Проверка здоровья панели выдерживает
  отсутствие разрешения на перечисление сетевых интерфейсов.

## Что сохраняется

Схема базы, существующие клиенты, UUID, пароли Hysteria, токены подписок,
настройки, ключи, frontend и установленная версия Xray не заменяются патчем.
Новые зависимости и миграции не нужны. Установочный и join-скрипты не запускаются.
Настройка NAT для AmneziaWG этим патчем не меняется.

## Проверки и границы результата

Исправления проверены автоматическими тестами. Сквозные локальные проверки
на настоящем Xray 26.3.27 проходят по цепочке клиент → мастер → Trojan/gRPC-нода
→ HTTP/HTTPS-сайт и UDP-echo. Проверены Reality TCP и Hysteria 2, включая
обратный ответ; исходящий адрес подтверждает использование ноды.
В тесте входной PROXY-заголовок Nginx воспроизводится TCP-реле.

Проверены TypeScript/production build и lint. Существующие предупреждения
React не относятся к этому патчу. Полный Nginx integration test пропускается,
если Nginx отсутствует; функции изменения/отката файлов проверены отдельно.

Доступа к реальному серверу и телефону в этой сессии нет. По прежнему журналу
Hysteria уже принимал запросы, а SOCKS-проверка получила HTTP 200 через ноду.
Это не доказывает причину последнего отказа телефона. Патч исправляет выявленные
ошибки проекта; восстановление соединения на вашем сервере нужно подтвердить
после обновления. DNS/Private DNS браузера, исключения приложений, блокировки
TCP/UDP, сертификаты и параметры реально импортированного профиля всё ещё
могут требовать отдельной диагностики.

## Обновление существующей панели

Распакуйте архив **отдельно от каталога установленной панели**. Например,
загрузите файл на сервер как `/root/md-next-network-fix.zip` и выполните:

```bash
mkdir -p /root/md-next-network-fix
unzip /root/md-next-network-fix.zip -d /root/md-next-network-fix
cd /root/md-next-network-fix/md-next-main
sudo python3 scripts/apply-network-fix.py --check
sudo python3 scripts/apply-network-fix.py --apply
```

Каталог активной установки определяется через systemd. При необходимости
добавьте `--app-dir /opt/md-next` к обеим командам.

Скрипт сверяет SHA256 девяти изменённых файлов с исходной и исправленной
версией. Если сервер отличается от присланного проекта, он останавливается
**до изменений**. Не обходите эту проверку: сначала нужно сопоставить версии.

При применении создаётся копия исходных файлов, конфигураций, `.env` и целостная
SQLite-копия БД в `/var/backups/md-next/network-fix-...` с закрытым доступом.
Панель кратковременно останавливается; применение изменённого Xray-конфига
перезапускает VPN и разрывает текущие сессии. Затем проверяются `/health`,
состояние Xray, синтаксис и основной маршрут рабочего конфига. При ошибке
восстанавливаются прежние исходники и конфигурации. Живая БД и `.env` при
откате не заменяются, чтобы не потерять данные, накопленные после копирования.

Не используйте пункт «Обновить» в старом `install.sh` для установки этого
архива: он загружает репозиторий GitHub и может затереть локальные исправления.

## После применения

1. В Happ обновите существующую подписку; выберите переданный профиль
   маршрутизации «MD-Next DNS», если он не активировался автоматически.
2. Полностью отключите и снова включите VPN, чтобы применились настройки DNS.
3. Проверьте оба профиля и браузер:
   `https://1.1.1.1/cdn-cgi/trace` и
   `https://www.cloudflare.com/cdn-cgi/trace`.
4. Если результата нет, выполните отчёт и пришлите его вместе с ошибкой Happ:

```bash
sudo /opt/md-next/backend/venv/bin/python scripts/diagnose-network.py --probe
```

При другом пути установки замените `/opt/md-next`. Отчёт читает конфигурацию
и БД без изменения, выводит только выбранные поля; не выводит приватные ключи,
пароли, UUID и ссылки подписок. `--probe` делает два HTTPS-запроса через SOCKS Xray.
Не присылайте целиком `.env`, базу данных или резервный архив.

## Ручной откат

Скрипт обновления печатает точную команду. Её общий вид:

```bash
sudo python3 scripts/apply-network-fix.py \
  --app-dir /opt/md-next \
  --rollback /var/backups/md-next/network-fix-ДАТА
```

Резервные копии содержат секреты и должны оставаться на сервере.

## Повторная проверка в разработке

```bash
cd backend
pytest -q
```

Тесты `test_xray_end_to_end.py` требуют `xray` и `curl` в PATH и не используют
внешние сайты или установленные systemd-сервисы. Реальные ключи/сертификаты
создаются только во временных тестовых каталогах.
